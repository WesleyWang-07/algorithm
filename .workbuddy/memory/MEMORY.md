## 本机环境坑（Windows）

- **`Bash` 工具的 PATH 残缺**：`ls`/`cat`/`head`/`tail`/`wc`/`dirname` 全部
  `command not found`，但 `cd` + 绝对路径调 Python 可用。定式：
  `cd "路径" && "C:/Users/wzy/AppData/Local/Programs/Python/Python312/python.exe" -c "..."`
- **`timeout` 命令会撞上 Windows 的 `timeout.exe`**（报"无效语法"），
  改用 Bash 工具自身的 `timeout` 参数。
- **`git update-ref refs/remotes/origin/main` 会静默失败**：本机 `.git/refs/remotes/origin/`
  目录不存在时，它返回 0 但不落盘，导致 `git status` 一直显示 `[origin/main: gone]`。
  **注意：`git push` 成功 ≠ 追踪引用已建立** —— push 输出正常、`git ls-remote origin` 也
  已是新哈希，但 `git status -sb` 仍报 `gone`（2026-09-18 再次复现）。
  **修法：先用 Python `os.makedirs` 建目录，再写 `main` 文件（内容为哈希 + 换行）。**
- **专利 PDF 是加密的**：`文献/20241016-发明-...pdf`（AESV2 / R=4），**密码 `stt`**。
  `pymupdf`：`d.authenticate('stt')` 返回 **2=owner / 1=user / 0=失败**，之后 `get_text()` 正常。
  **别用 `insert_pdf` 另存解密副本**（抛 `aes padding out of range` 后失败）。
  它的**真文本层**已导出为 `文献/patent_text_layer.txt`，比 `patent_p*_*.txt`（OCR 版）权威。

## 「不追逐 0.524」的**完整**理由（2026-09-17 第六轮后定稿）

ADR 0001 的决定成立，但**经过两次加固**，现在的理由是三条叠起来的：

1. **δ₂ 带枚举选不出 77**（第三轮，40 种组合无一命中；已按正确口径重跑，仍无一命中）；
2. ~~论文的 δ 是"以中点为心的对称带"，旧枚举漏试了~~ **← 这条 2026-09-18 证伪。**
   论文 **3.4.2（p53）** 用**五组 δ 范围对比实验**定下 δ₂=(2/7·M, 3/5·M)（**实验三**），
   **与本实现所用之带一致**；**实验五 (2/9·M, 7/9·M) 才是中点对称带，已被论文否决**。
   → "δ 带取错"从来不是变量，这条理由**作废**（理由 1 与 3 两条已足够）。
3. **B 指标退化**（`diag_l2_band_center.py` 的副产品）：右簇内终点列恒为 col 111
   ⇒ B = 111−c0 **严格单调** ⇒ **带若落在右簇内，选中列恒等于带的右边界**。
   `[71,77]`"命中"77 就因为 77 是它的右边界。
   **→ "让锚点=77"不构成对算法的检验，这正是被否决的"反向拟合"的形态。**

> 📌 **B 退化不是我发现的**：论文 §3.4.3 已写明"指标B/C 为追求更小偏移量而选择了
> 熔断路径、导致切分错误"。我做的是**把它量化到机制层**。当着作者（沈添天）的面

## 术语歧义（重灾区，已在 CONTEXT.md 立规）

- **「指标层」≠「度量口径」**：前者指 A/B/C/D 选优，后者指 `c/W` 的定义。
  这两个问题曾被混成一个，导致浪费一轮研究。
- **`j=4` 是"右侧"、`j=5` 是"左侧"**：相对前进方向 g 而言，**不是图像坐标的左右**。
  在 l₁（g 向右）里 j=4 指的是**下方**。
- **「熔断」与「选优」是两件独立的事**：混成一件会在错误方向施工（第二轮教训）。
