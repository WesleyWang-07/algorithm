# 论文表格结果图不能当"像素级真值"

**状态**：已采纳（2026-09-18）

## 决定

本项目**不再尝试**用"本实现轨迹与论文图上画的切分线是否重合"来度量切分正确率。
论文表3-3 / 表3-4 里那 40 张结果图（`tab33_rNN_A~D.png`）**只允许当作定性参照**，
不允许参与任何"一致率"式的定量结论。

仍在用的、被判定为**合法**的度量只有一个：

> **同一把尺子下的穿墨量** —— 把论文的线与本实现的轨迹分别叠在**同一张干净字形**上，
> 数各自压在墨迹上的像素。两边必须先统一线宽（论文线 3px、本实现轨迹 1px）。

## 为什么

### 证据 1：15 行里有 5 行"结果图与字形图不是同一块画布"

判据：把结果格的红/绿像素剔掉后，剩下的墨迹与字形格逐像素比，放宽到 8 邻域膨胀 1px。

| 行 | 字形格 | 结果格 | 膨胀 1px 后残余差 | 判定 |
|---|---|---|---|---|
| tab33 #1~#10 | H×182 | H×183 | 1 ~ 4 | **同格**，可比 |
| tab34 #1 | 250×182 | 250×183 | 200 | 不同画布 |
| tab34 #2 | 258×182 | 257×183 | 817 | 不同画布 |
| tab34 #3 | 298×182 | **323**×183 | 15386 | 不同画布 |
| tab34 #4 | 310×182 | **346**×183 | 13792 | 不同画布 |
| tab34 #5 | 274×182 | **264**×183 | 4237 | 不同画布 |

**表3-4（5 个粘连字）整表不可坐标比较** —— 而粘连字恰恰是"能不能做到"最关键的那一半。

> 注意：表3-3 同格，所以"逐列比行号"这件事本身是成立的。问题不在格子，
> 而在下一条。

### 证据 2：论文画的 l₂ 起点列，在表3-3 十个字上恒为 72

| 指标面板 | 10 个字的 l₂ 起点列 |
|---|---|
| A | 72, 72, 72, 72, 72, 72, **73**, 72, 72, 72 |
| B / C | 72, 72, **76**, 72, 72, 73, **75**, 72, **80**, **84** |
| D | 72, 72, **76**, 72, 72, **73**, 73, 72, **78**, **84** |

- 十个字形**宽高各不相同**（182×216 … 182×283），但 l₂ 起点列几乎一律是 **72**；
- 72 / 182 = **0.396 ≈ 0.40·W**，与字形内容无关；
- 其中 **3 个字（#1、#4、#8）的四个指标面板的绿线逐像素完全相同**。

⇒ 这些绿线更像"按一个固定比例画上去的标注线"，而不是"四个指标各跑一遍得到的轨迹"。

### 证据 3：论文自己的 l₂ 线也会切穿笔画

表3-3 上，把论文的绿线叠回干净字形，按 3px 线宽统计，**合计压墨 131 像素**
（单字 0 ~ 30）。而论文 §3.4.3 判定表3-3 的 1~9 号字"各优化指标切分结果均完全正确"。

⇒ **"切线必须走在空白通道上"不是论文的判据。**
所以本 ADR 当初设想过的那个自动化判据（"穿墨 = 切分错"）**是错的**，已放弃。
（这条也顺手解释了为什么不能用"零穿墨"当自动真值。）

## 由此得到的、仍然有效的结论

1. **能用同一把尺子比了**：表3-3 十个字上，**本实现 l₁ 穿墨 211 像素 vs 论文 745 像素**；
   l₂ 是 **267 vs 131**（本实现偏多，主要来自 #9 一个字）。
   即：l₁ 上本实现切得比论文所画的线更干净；l₂ 上不如，且差距集中在一个字上。
   逐字对照图见 `汇报/figs/fig4_论文真值对照.png`（`diagnostics/diag_paper_lines_overlay.py`）。
2. **"切分正确率"这个数，本项目给不出。** 论文用的是人工判定；
   自动判据（穿墨量）已证明与论文的判定口径不一致。
   论文自己的集级数字是表3-5 / 表3-6：谱字集A 99.06%、集B 95.53%（D 指标）。
3. **表3-4（粘连字）在本项目里只能定性说"跑得通"**，不能给数字。
