# 真实谱字校验报告（诚实版）

> 目的：把算法从"合成演示"换到论文里的**真实手写减字谱字**上再跑一遍，并校验是否正确。
> 输入：`../文献/glyphs/p49_img4.png`（论文图3-24/3-25 里的完整谱字，纸本扫描，已剔除红线）。
> 真值：论文原文（[论文.md:154-156,134](/d:/Study/算法学习/文献/论文.md#L134-L156)）明确该谱字 = **左上=大指"大"、右上=徽位"七"、下=右手指法"勾"**，切分目标为 **左上 / 右上 / 下** 三块。

## 一、结论先讲

| 环节 | 结果 |
|---|---|
| 代码在真实图上运行 | ✅ 正常运行，无异常 |
| **第一次切分（水平滴，上下分）** | ✅ **基本正确** —— 滴放落点 `row≈95`，与论文自绘红线上段 `row≈94` 吻合 |
| **第二次切分（竖直滴，左/右上分）** | ❌ **漂移** —— 滴放滑到 `col≈111`，而真正的大/七分界带在 `col≈60-80` |
| 像素级 IoU 校验（三块裁剪 vs 大/七/勾） | ❌ **不可靠** —— 穷举所有横+竖切分点，最好也只有 IoU≈0.57 且 **0/3 匹配** |

## 二、为什么第二次切分（竖切）对不上

1. **大和七在真实图上是连成一体的**。连通分量分析显示：上、下各是一个整体墨块（上=1308px 单连通），并非分离的三块。视觉确认它上半是一根连贯的"匚框"横笔。
2. **因此没有一条能"笔直向下切分大/七"的竖直缝隙**。逐列空隙深度剖面显示，中部墨区（col6-122）几乎每一列的顶部竖直空隙只有 ~20-28px 就撞到墨（那根连通横笔）。真正的任意竖直滴从 col51-96 起，**全部在 (185,92) 右下角收尾**——它沿连通横笔的轮廓**横滑绕行**，而不是向下劈开。
3. 这正是论文 **§3.4.4 "字符笔画粘连情形"** 单独当作难点处理的工况：需要**熔断**在上部横笔的合适位置将其斩断、并配合精心选择的初始滴点。这一套调参在扫描版专利 + 论文 md 里**无法被完整还原**。

## 三、为什么"像素 IoU 校验"本身不可靠

- **红线压墨**：论文图里红线与墨迹重叠，我在剔除红线时把勾等部位的实际墨迹也擦掉了一块，导致"剔除红线后的图"与"未受干扰的真值部件"天然对不齐。
- **bbox 归一化失真**：把每个裁剪块压到 48×48 会抹掉纵横比信息，结果"上区（大+七，宽 116）"vs"大（宽 78）"归一化后形状差异被夸大。
- **部件未必与本图对应**：`p49_img1/2/3`（勾/大/七）与 img4 各区域的最佳 IoU 均在 0.1~0.3 之间（近乎噪声），说明这几张提取部件与本图的切分区不存在干净的一一对应。

## 四、真正可复现、可信的验证

对**无粘连结构明确**的谱字（也就是老师给的那张"红色横线+绿色竖线"样例），本实现**完整复现**：
`demo_segment.py` 输出的 `output/overlay_无粘连.png` 即：红线（水平滴，上下分）+ 绿线（竖直滴，上左右分），得到 左上/右上/下 三块。这一路线是论文的核心成果，也是提交给老师最稳妥的演示。

## 五、坦诚定位

- 对**结构清晰（无粘连或粘连可控）**的减字谱：实现正确、可视化与老师样例一致。
- 对**真实手写、笔画粘连**的谱字：代码能跑，第一次切分命中，第二次竖切因墨迹粘连而漂移，且**无法用"裁剪块 vs 提取部件做 IoU"来给出可靠判定**。要复现论文在粘连字上的 99.06%，还需论文里未完整给出的初始滴点优化 + 熔断断笔规则（§3.4.4）。

## 六、如何运行

```bash
python demo_segment.py   # 无粘连谱字：红+绿双向切分，出 overlay 与三块子图（复现老师样例）
```
