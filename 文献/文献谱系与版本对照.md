## 五、关键实验：起点范围 ──「论文 δ 带」 vs 「专利全宽」

### 5.1 疑点从哪来

`segment.py` 第 87 / 114 行的注释标注的出处是「**论文**」：

```
87| # 论文: 上下切分初始滴点 δ1 ∈ (2/5 N, 3/5 N), N=高度(行数)
114| # 论文: 左右切分初始滴点 δ2 ∈ (2/7 M, 3/5 M), M=宽度(列数，上方区域)
```

而**专利里根本没有 δ 带**，权利要求 5 写的是**全范围枚举**：

```
5.2 设置大小为 M×N 的矩阵 P 记录被切分图像大小。
    初始滴点的像素坐标为 (x_o, y_o)，其中 x_o ∈ [0, M]，y_o = 0
```

> **注：专利此处自身前后不一致。** 权利要求 4 定义坐标系「x 轴竖直向下、y 轴水平向右」，  
> 并写 `x_i ∈ [0, N], y_i ∈ [0, M]`；而权利要求 5 写成 `x_o ∈ [0, M]`。  
> 按权利要求 4 的定义（M=宽度、N=高度），权利要求 5 的 `x_o ∈ [0, M]` 应为 `x_o ∈ [0, N]`。  
> 无论取哪个，**都是全范围枚举，不构成 δ 带**。

于是产生一个真问题：**实现用的 δ 带属于论文，而不是专利 —— 这是否偏离了专利？**

### 5.2 对照实验（`diagnostics/diag_fullwidth_vs_band.py`，只读）

在真实谱字 `p49_img4.png`（185×147）上，把起点范围换成全范围，重跑选优：

| 切分           | 范围                         | 选中指标最优      | 四指标 A/B/C/D       | 终点           |
| ------------ | -------------------------- | ----------- | ----------------- | ------------ |
| l₁（metric D） | **δ₁ 带** rows 74–110（当前实现） | r0 = **95** | 5 / 1 / 3 / 9     | —            |
| l₁（metric D） | **全范围** rows 1–183         | r0 = **1**  | 0 / 1 / 1 / 2     | —            |
| l₂（metric B） | **δ₂ 带** cols 42–87（当前实现）  | c0 = **46** | 12 / 0 / 10 / 22  | **(96, 46)** |
| l₂（metric B） | **全范围** cols 1–145         | c0 = **4**  | **0 / 0 / 0 / 0** | **(94, 4)**  |

> ⚠️ **2026-09-18 更正**：本表原记为 `r0=92 / 5-0-2-7 / 全范围 r0=1`、
> `l₂ 全范围 c0=1 / 终点 (92,1)`。`92` 系列源自**读图口径错误**（`convert('L') < 128`
> 把图内烤着的论文红线当墨迹）；按正确口径 **RGB 逐通道 `<128`** 重跑后即为上表。
> 复核命令：`python 专利滴水算法实现/diagnostics/diag_fullwidth_vs_band.py`。

### 5.3 结论（方向与"实现有错"的猜测**相反**）

全范围枚举会选到 **row 1 / col 4**，即贴近图像最边缘。原因很直接：

**本项目的谱字图带留白边距，最外圈是空白通道。水滴从边缘出发会一路直落、  
完全不接触墨迹，于是熔断 0、偏移 0 —— 四项指标全部取到最小值。**

`l2 FULL` 那一行的 `[0, 0, 0, 0]` 就是它的指纹：一个**平凡解**。  
按这个解切出来的线会贴着图像边框走过，**切不出任何有意义的内容**。

因此：

1. **δ 带不是"混进实现的论文私货"，而是让算法有意义的必要约束** ——  
   它的真实作用是把先验「切分线必须穿过谱字中部」编码进候选集合；
2. **专利的 `x_o ∈ [0, M]` 若字面实现会退化**。专利正文很可能省略了  
   δ 这一层（或默认输入图像已裁剪到笔画包围盒、边缘必然有墨迹）；
3. **当前实现的取法（δ₁ 对称 + δ₂ 偏左）在实践上站得住**，  
   但**注释应改标为"论文/工程约定"，不能标成"专利"**。

> **前提声明**：上述退化结论依赖"图像边缘无墨迹"。  
> 若换成边缘即为墨迹的紧包围盒图像，全范围枚举不会退化为平凡解。  
> 古琴谱字的实际切分场景含留白边距，故该结论成立。

## 八、2025 CCC 可能带来的优化点（**待全文核实，以下不是结论**）

> 用户 2026-09-18 提问：「这篇论文对我现有的项目能否优化」。  
> 手头只有摘要 → **无法负责任地回答"能/不能"**。  
> 但摘要里有两处**点名了、而专利没写清**的机制，可作为优化的候选点。

### 8.1 专利留白的两件事

专利 3.1 / 3.2 只定义了两样东西：

- `k` 的三个取值及语义（0=初始、1=偏右、-1=偏左）；
- `o_j` 的公式（方向门控：`k=1` 时右侧为正、左侧为负）。

**专利从未说明：**

1. `k` **何时**从 0 变成 ±1（随机赋值的时机）；
2. `k` **何时、按什么规律**改变符号。

而图13–15 里 `k` 明显在反复翻转（例：`k=1 → k=-1`，`k=-1 → k=1`），  
说明这两条规律**客观存在**，只是权利要求书里没写。

**2025 CCC 摘要恰好把这两件事说出来了** —— 这是它相对专利的增量信息。

### 8.2 逐条对照

| 机制          | 2025 CCC 摘要原文                                                                        | 本项目实现（`improved_droplet.py`）                                       | 判定          |
| ----------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ----------- |
| k 初始化       | "**initialized as zero**"                                                            | 第 184 行 `k = 0`                                                    | ✅ 一致        |
| **随机赋值时机**  | "randomly assigned right or left **when first blocked by the directly below point**" | 第 206–212 行：首次遇阻时赋值（`oriented` 标志），触发条件为「`Q≤0` 或胜出邻点为后向 `j∈{6,7}`」 | ⚠️ **表述不同** |
| **k 的调整规律** | "then adjusted conforming to an **inertia principle**"                               | 仅在**回流（reflow）**&#x65F6; `k = -k`（第 134 / 159 行，无条件翻转）             | ⚠️ **待核**   |

### 8.3 两个候选差异点（**不要据此改代码**）

**差异点 1 — 随机赋值的触发条件**

- 摘要：被「**正下方**」阻挡（the directly below point，即 `j=1`）时赋值；
- 实现：「`Q≤0` 或胜出邻点为后向 `j∈{6,7}`」时赋值。

两者**并不等价**：正下方为黑时 `z_1 = 0`，但只要其他白邻点存在，  
`Q` 仍可能 `> 0`（例如侧向 `j=4` 开着）。此时按摘要**应**赋值 `k`，  
按实现**不会**赋值。

> 附注：项目第三轮曾实测过「`c0=77` 出发，`r=21` 被迫侧滑（`j=1/2/3` 全黑，  
> 胜出 `j=4 Q=4`）」—— 这正是"正下方黑、但侧向开着"的情形。  
> 该情形下实现**没有**触发随机取向（全程 `k≡0`）。**若论文规则要求触发，  
> 则此处行为会不同。**

**差异点 2 — 「惯性原则」是什么意思**

- 摘要：「按**惯性原则**调整」；
- 实现：回流时**无条件翻转** `k = -k`。

"惯性"在字面上意味着**倾向保持原状态**，与"直接翻转"方向相反。可能有两种解释：

- (a) 实现正确，摘要的 "inertia" 只是描述"`k` 会延续、直到被迫改变"这一总体现象；
- (b) 论文的规则更细（例如"连续受阻才翻转"或"翻转后设惯性期"），实现偏简。

**目前无法判定，须见全文。**

### 8.4 **更重要的发现：方向变量在主流程里是关闭的**

这一条比 8.3 的两个差异点更实质。

**`segment.py` 默认 `seed=None`** → `make_rng()` 返回 `None`  
→ `drop_improved` 里只有 `rng is not None` 才给 `k` 赋值（第 211–212 行）  
→ **整个枚举过程中 `k ≡ 0`**  
→ 而 `k = 0` 时 `o_j ≡ 1`（`_theta_j` 第 76 行）  
→ **方向门控完全关闭。**

也就是说：2025 CCC 摘要里并列的两个机制 ——  
① "expands the gravity potential window with two splashing positions"（窗口扩展）  
② "adjusts the allocation of window weights based on a direction variable"（方向变量）  
—— **本项目主流程只启用了 ①，② 处于关闭状态。**

#### 实测对照（`diagnostics/diag_orientation_effect.py`）

同一谱字 `p49_img4.png`，`metric='D'` / `metric2='B'`：

| 模式                    | l₂ 起点       | 交点           | l₂ 四指标 A/B/C/D        | l₁ 四指标  |
| --------------------- | ----------- | ------------ | --------------------- | ------- |
| `seed=None`（默认，`k≡0`） | (0, **46**) | (96, **46**) | 12 / **0** / 10 / 22  | 5/1/3/9 |
| `seed = 1…20`（开启随机取向） | (0, **42**) | (96, **33**) | 13 / **9** / 19 / 41 | 5/1/3/9 |

> ⚠️ **2026-09-18 重跑更正**：本表原记 `(92,46)/(92,32)`、`13/10/18/41`、`5/0/2/7`。
> 那是 `diag_orientation_effect.py` 当时的**读图口径错误**造成的 ——
> 它用 `convert('L')` 读图，而 `p49_img4.png` 内**烤着论文自己的红线标注**
> （247 个纯红像素，rows 94–184）；纯红灰度 L≈76<128 ⇒ **红线被判成墨迹**
> ⇒ l₁ 贴着论文红线走到 row 92。改为 RGB 逐通道口径后即为上表。
> **定性结论不变**（交点列 46→33、l₂ 的 B 由 0 恶化到 9、l₁ 不受影响）。

**三点观察：**

1. **结果显著不同**：交点列 46 → 33；l₂ 的 B 指标由 **0 恶化到 9**  
   （B = 始末偏移量，即 l₂ 从"完全竖直"退化为"偏了 9 列"）；
2. **20 个不同种子给出完全一致的 `(96, 33)`** —— 说明这不是随机噪声，  
   而是**结构性差异**（在该图上，取向一旦开启就稳定地改变路径）；
3. **l₁ 完全不受影响**（四指标恒为 5/1/3/9）—— 差异只出现在 l₂。

> 「20 个种子结果一致」本身是个**待解现象**：  
> 若 `k` 真的按 ±1 随机取值，不同种子本该给出不同结果。  
> 可能的原因是该图上 `k` 的取值最终不影响落点，或取向触发点唯一。  
> **此现象已记录，未深究。**

#### 这算 bug 吗？**不算。**

`segment.py` 的 docstring 明确解释了默认 `seed=None` 的理由：

> 「枚举时关闭 S102 遇阻随机取向（k 恒 0）：同一候选的指标恒定、候选之间可比，  
> 这是"枚举选优"能稳定复现零漂移解的前提」

这是**有意的设计权衡**，不是疏漏。

#### 但它意味着什么（这才是重点）

**本项目目前验证的，是「7 邻点窗口 + 方向门控关闭」的算法形态，  
而不是专利/论文完整的"双向飞溅"算法。**

方向门控关闭时，水滴在每一格都能自由选择任意方向（两侧等价竞争）；  
门控打开后，一侧会被强制屏蔽、水滴被推向另一侧。  
**这是两种不同的动力学。**

因此项目当前的全绿结论（11/11、400/400、零熔断、MATLAB 对照）  
**只覆盖了机制 ①，未覆盖机制 ②**。

### 8.5 另一类可借鉴项：横向对比实验

摘要："demonstrate its advantages **over other dripping algorithms**"  
→ 论文含**与其他滴水算法的对比实验**。  
本项目目前只有**自洽检验**（11/11、400/400、零熔断、MATLAB 对照），  
**没有横向对比**。这是可补的一类工作。
