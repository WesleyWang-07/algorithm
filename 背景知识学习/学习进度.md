**我的记录**（2026-09-06 完成，答案由辅导对话填入）：

### 第 2 步：玩 —— 亲眼看"浅坑死锁"（约 20 分钟）

```bash
cd "D:/Study/算法学习/背景知识学习"
python 练习-mini_drop.py
```

把文件第 26 行 `r, c = 0, 1` 的列号依次改成 `2` 和 `3` 各跑一次。
**先猜再跑**：三种起点，两条会卡死在浅坑、一条能滑到底——先猜哪条能逃逸，再验证。

**自查**：卡死的两条轨迹末端有什么共同点？逃逸的那条绕过了坑的哪一边？

**我的记录**（2026-09-07 完成，第三次运行 c=3 时曾报 `IndexError: list index out of range`，
排查后发现是练习文件自身的边界 bug：`H, W = 6, 6` 但 `ink` 只有 5 行，已改为 `H, W = 5, 6`。
三组实际轨迹（`path` 末段）：

| 起点 | 我的猜测（卡死/逃逸） | 实际结果 | 轨迹末段 |
|---|---|---|---|
| c=1 | | 卡死 | `(2,2),(2,3),(2,2),(2,3),…` 在浅坑两格间往返 |
| c=2 | | 卡死 | `(1,3),(2,3),(2,2),(2,3),…` 同样在浅坑两格间往返 |
| c=3 | | 逃逸 | `(0,3),(0,4),(1,5),(2,5),(3,5),(4,5)`，落入最底行后在底行水平往返 |

**自查答案**：
1. 两条卡死路径的末端共同点：都在 `(2,2)` 与 `(2,3)` 之间**成对往复**——先往右再往左、
   再往右再往左，这就是传统 6 条规则的"水平往复循环"（浅坑死锁）的直观形态；
   规则 4/5（左右滑动）优先级相同且无记忆，所以永远出不去。
2. 逃逸的 c=3 绕过了坑的**右边**：正下/右下/左下全被挡时，水滴按规则 4 沿顶行右侧滑到
   (0,4)，再按规则 2 斜落到 (1,5)，之后沿最右列一路滑到底——绕开了浅坑的右壁。
3. 附赠的边界教训：底行水滴探测"正下方"时 `r+1` 越界——`H` 必须等于 `len(ink)`。
   练习文件里 `H, W = 5, 6` 是修复后的值。
