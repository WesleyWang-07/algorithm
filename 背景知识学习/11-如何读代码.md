## 0. 一句话方法论

读代码不是从第一行啃到最后一行，而是**带着问题去找到答案**，五步：

```
① 读"说明书"（文件开头的注释）
② 找"入口"（谁会被外部调用）
③ 画"零件地图"（每个函数一句话）
④ 先读注释、再对代码（核心函数）
⑤ 代入具体数字，跟代码对答案   ← 最重要，别跳过
```

## 1. 第一步：先读"说明书"，不读代码

打开文件别看代码，先读第 2~21 行的三引号大段文字。它是作者写给你的中文说明书：

- 这个文件实现了专利的哪四条（S101~S104）；
- 坐标怎么约定（`img[r, c]`：r=行、c=列，与专利的 (x,y) 一致）；
- 重力方向 `g` 可以是任意方向——所以"横着切"（l1）和"竖着切"（l2）共用同一份规则。

**这一段读完，你已经懂了 80% 的设计意图**，后面代码只是把意图翻译成机器指令。

## 2. 第二步：找"入口"——谁是被外面调用的

一个文件里通常只有少数函数是给别人用的。先问：**别人会调用谁？**

- `drop_improved`（第 164 行）与 `path_metrics`（第 269 行）是入口——`segment.py` 和测试脚本调用它们；
- 其余函数都带 `_` 前缀（`_neighbors`、`_q_decision`…）。这是 Python 的约定：
  **下划线开头 = 内部零件，外人不用管**。

然后读入口函数的参数注释（164~177 行）：输入 = 黑白图 `ink`、起点 `(r0,c0)`、重力 `g`；
输出 = 字典（走过的 `path`、熔断数 `melt`……）。**读函数永远先读"吃什么、吐什么"，再读中间。**
函数名本身也是线索：`drop_improved` = "改进滴水"、`is_open` = "是否可走"。

## 3. 第三步：画零件地图，按"从易到难"顺序读

文件拆成 7 块，建议顺序：

| 顺序 | 行号 | 函数 | 一句话职责 | 难度 | 关联讲义 |
|---|---|---|---|---|---|
| 0 | 2-21 | 说明书 docstring | 讲这个文件干什么 | ★ | — |
| 1 | 41-51 | `perp_of` / `is_open` | 算右方；问"这个格子能走吗" | ★ | 02 |
| 2 | 54-65 | `_neighbors` | 7 个邻点各自在哪（位移表） | ★ | 02 |
| 3 | 68-80 | `_theta_j` | 由 k 决定每个方向的符号（正/负） | ★★ | 04 |
| 4 | 83-105 | `_q_decision` | 给 7 个邻点打分，取最高分 | ★★★ | 04 |
| 5 | 122-161 | `_step_patent` | 按分数决定动作（滴落/飞溅/回流/熔断） | ★★★ | 04 |
| 6 | 164-253 | `drop_improved` | 主循环：反复走步，直到出水或停止 | ★★★ | 04/05 |
| 7 | 259-280 | `metric_B` / `path_metrics` | 给走完的路径打 4 个分 | ★★ | 05 |

**每读一个函数，用一句话写下它的"输入 → 输出"。** 例如：

- `is_open(ink, r, c)` → 这个格子能不能走（白=能走，黑=不能走）；
- `_neighbors(g)` → 重力方向 g 下，7 个邻点各自的相对位置；
- `_q_decision(...)` → 最高"分数"是多少、是哪个邻居。

能写出来这一句，函数就算读完，**不用背细节**。

## 4. 第四步：核心函数——先读注释，再对代码

### 4.1 `_step_patent`：把注释当"翻译表"

第 108~121 行的注释块就是一张 Q 值→动作的翻译表（抄自专利图4~图12）。读法：
先读这张表，再扫代码确认**每个表项都有一个 `if` 分支**。例如表里"Q=7 正前方滴落"，
代码第 137 行就有 `if j == 1: return ('move', ...)`。一一对上，函数就懂了。

### 4.2 `_q_decision`：全文件的心脏（多花 5 分钟）

```python
best_j, best_q = None, None
for j in range(1, 8):             # 挨个看 7 个邻居
    if not is_open(...):          # 黑格子？跳过（不参与打分）
        continue
    q = _G7[j] * _theta_j(j, k)   # 白格子：权值 × 正负号
    if best_q is None or q > best_q:
        best_q, best_j = q, j     # 记住目前最高分
if best_q is None:
    return None, 0.0              # 一个白格子都没有 → Q=0
return best_j, best_q
```

注意最后的 `if best_q is None` 小心思：它把**"周围全黑"（Q=0，要熔断）**与
**"只有反方向有白"（Q 是负数，要回流）**区分开了。这是算法的精度所在。

## 5. 第五步（最重要）：代入具体数字，跟代码对答案

抽象读十遍，不如**拿一个具体局面代进去走一遍**。

**例 1（浅坑飞溅）**：滴点在 (2,2)，周围只有右上 (1,3) 和左上 (1,1) 两个白格子，k=1、s=0。

1. 手算打分（对着 `_q_decision`）：
   - 邻居 j=6 在 (1,3)，白 → 分数 = 权值 2 × 符号 `(-1)^6 = +1` → **+2**；
   - 邻居 j=7 在 (1,1)，白 → 分数 = 权值 1 × 符号 `(-1)^7 = -1` → **−1**；
   - +2 更大 → **j=6，Q=2**。
2. 对决策表（`_step_patent`）：Q=2 → 浅坑；s=0 → **飞溅**：跳到 (2−1, 2+1) = **(1,3)**，s 变成 1。
3. 对答案：跑 `python test_patent.py`，第 6 条 PASS 写着"move 到 (1,3), s=1"——**和手算一样**。

**例 2（回流）**：只有左侧三个格子白，k=1。
三个分数全为负（−5、−3、−1）→ 最大者为负 → **Q<0** → 回流：原地不动、k 变 −1、s+2。
同样可在 `test_patent.py` 第 10 条对答案。

> 这个"**猜 → 跑 → 对答案**"的循环，就是读算法代码的正确姿势。

## 6. 不认识的语法？这个文件只用了这几样

| 写法 | 一句话解释 |
|---|---|
| `{j: 8 - j for j in range(1, 8)}` | 建表（字典推导式）：j=1…7 各配一个权值 |
| `(r, c)`、`act[0]` | 元组：把几个数打包；`[0]` 取第几个 |
| `x in (6, 7)` | 等于 6 或 7 就为真 |
| `nonlocal r, c` | "下面我要改外层函数的变量"（`_record` 里用） |
| `_开头的名字` | 内部零件，外部不调用 |

## 7. 代码里的两个"边界小心思"（读到时想一想）

1. **第 231 行的兜底熔断**：如果下一步要落回原位置或走过的点，强制熔断——防原地死循环；
2. **第 222~225 行处理 `s > 5`**：专利状态表只定义到 5，超出就保底熔断。

这两处是"代码在替算法边界擦屁股"——正式论文里看不到，真实工程里到处都是，很值得体会。

## 自查（答案在文末，先自己想）

- Q1：为什么不带 `_` 前缀的函数值得**先**读？
- Q2：`_q_decision` 返回 `(None, 0.0)` 代表什么局面？为什么不直接返回 `(6, 0)`？
- Q3：手算：滴点 (2,2)，只有正前方 (3,2) 是白，Q=？动作是什么？

---

**自查答案**：

1. 不带 `_` 的是给外部用的"入口"，它们决定了整个文件的用途和输入输出契约；
   内部零件是围绕入口服务的，先看入口才知道每个零件为什么存在。
2. 代表"周围 8 个邻点全黑"（Q=0 → 熔断）；`(6, 0)` 会误导调用方以为"赢家是 j=6"，
   所以用 `None` 明确表示"没有赢家"，让主循环能用 `Q == 0` 判断熔断。
3. Q = 权值 7 × 符号 1 = **7**；动作 = **滴落**：走到 (3,2)，s 归 0
   （`test_patent.py` 第 1 条 PASS 就是它）。
